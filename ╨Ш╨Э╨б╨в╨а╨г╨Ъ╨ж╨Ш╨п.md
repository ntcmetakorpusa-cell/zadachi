# Запуск сайта «Задачі підприємства»

Время: около 30 минут, один раз. Всё бесплатно, банковская карта не нужна.
Понадобится компьютер (не телефон) и ваш Google-аккаунт.

Файлы из архива: `index.html`, `app-core.js`, `config.js`, `seed.js`, `firestore.rules`, `manifest.json`, `icon.svg`, `icon-192.png`, `icon-512.png`.

---

## Часть 1. Сайт на GitHub (10 минут)

1. Зарегистрируйтесь на **github.com** (кнопка *Sign up*). Логин запомните: он будет в адресе сайта.
2. Справа вверху нажмите **+** → **New repository**.
   - *Repository name*: `zadachi`
   - Оставьте **Public** (на бесплатном плане сайт работает только из публичного репозитория; данных и паролей в файлах нет).
   - Нажмите **Create repository**.
3. На странице нового репозитория нажмите ссылку **uploading an existing file**.
4. Распакуйте архив и перетащите **все файлы** в окно браузера. Внизу нажмите **Commit changes**.
5. Откройте **Settings** (вкладка вверху) → слева **Pages**.
   - *Source*: **Deploy from a branch**
   - *Branch*: **main**, папка **/ (root)** → **Save**.
6. Через 1–2 минуты обновите страницу: вверху появится адрес вида
   `https://ВАШ-ЛОГИН.github.io/zadachi/`. Это ссылка на ваш сайт. Пока он покажет красную плашку «Сайт ще не підключено до бази» — это нормально.

## Часть 2. База данных Firebase (15 минут)

7. Откройте **console.firebase.google.com**, войдите своим Google-аккаунтом.
   **Create a project** → имя `zadachi` → Google Analytics можно **выключить** → **Create project**.
8. **Подключите сайт к проекту.** На главной странице проекта нажмите значок **</>** (Web).
   - Имя приложения: `zadachi`. Галочку *Firebase Hosting* **не ставьте**. → **Register app**.
   - Появится блок `const firebaseConfig = { apiKey: "...", ... }`. Не закрывайте эту страницу.
   - В другой вкладке откройте на GitHub файл **config.js** → значок карандаша (*Edit*).
   - Замените каждое `ВСТАВТЕ_СЮДИ` на соответствующее значение из Firebase (в кавычках). → **Commit changes**.
   - Эти значения не секретные: защита обеспечивается паролями и правилами из шага 12.
9. **Включите вход по паролю.** В Firebase слева: **Build → Authentication** → **Get started** →
   вкладка **Sign-in method** → **Email/Password** → включите первый переключатель → **Save**.
10. **Создайте три раздела.** Вкладка **Users** → **Add user**, три раза:

    | Email (логин) | Пароль |
    |---|---|
    | `director@zadachi.example` | пароль директора |
    | `vyrobnytstvo@zadachi.example` | пароль производства |
    | `administratsiia@zadachi.example` | пароль администрации |

    Пароли придумайте сами: от 10 символов, буквы и цифры. **Запишите их.**
    Адреса вымышленные, письма на них не приходят — это просто логины.
11. **Закройте регистрацию посторонним.** Вкладка **Settings** →
    - **User actions** → снимите галочку **Enable create (sign-up)** → **Save**.
    - **Authorized domains** → **Add domain** → `ВАШ-ЛОГИН.github.io` → **Add**.
12. **Создайте базу и правила защиты.** Слева **Build → Firestore Database** → **Create database**.
    - *Location*: `europe-central2 (Warsaw)` или любая европейская → **Next**.
    - **Start in production mode** → **Create**.
    - Откройте вкладку **Rules**, удалите весь текст, вставьте содержимое файла **firestore.rules** → **Publish**.

## Часть 3. Первый запуск (5 минут)

13. Откройте ваш сайт `https://ВАШ-ЛОГИН.github.io/zadachi/` (если открыт — обновите страницу).
14. Выберите **Директор**, введите пароль директора → **Увійти**.
15. Откроется экран «Налаштування доступу». Введите пароли **Виробництва** и **Адміністрації** из шага 10.
    Галочка «Додати 24 стартові задачі» добавит шаблон задач. → **Завершити налаштування**.
16. Готово. Сайт работает: можно ставить задачи и назначать ответственных.

## Часть 4. Сотрудники

- Отправьте каждому **ссылку на сайт**, название **раздела** и **пароль раздела** (лично, не в общий чат).
- Сотрудник открывает ссылку в любом браузере, выбирает раздел, вводит пароль. Никаких аккаунтов не нужно.
- На личном телефоне: отметить «Запам'ятати на цьому пристрої», затем в меню браузера **«Добавить на главный экран»** — сайт откроется как приложение.
- Все изменения синхронизируются между телефонами, ноутбуками и компьютерами за секунды.

## Пароли

- Менять пароли можно прямо на сайте: войдите как директор → **Паролі**. Нужен текущий пароль раздела и новый.
  После смены сотрудники этого раздела выйдут на всех устройствах и войдут с новым паролем.
- **Пароль директора терять нельзя.** Восстановить зашифрованные данные без него невозможно.
  Храните его в надёжном месте (например, в менеджере паролей или запечатанным у себя).
- Меняйте пароли только на сайте, **не в консоли Firebase**: иначе пароль входа и ключ шифрования разойдутся, и раздел не сможет открыть задачи.

## Если сотрудник уволился

Директор → **Паролі** → смените пароль его раздела и сообщите новый остальным.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| Красная плашка «Сайт ще не підключено до бази» | В `config.js` остались `ВСТАВТЕ_СЮДИ` или кавычки стёрты. Проверьте шаг 8, подождите 1–2 минуты и обновите страницу. |
| «Помилка входу (auth/operation-not-allowed)» | Не включён Email/Password, шаг 9. |
| «Невірний пароль» при правильном пароле | Проверьте логины в шаге 10: они должны совпадать буква в букву. |
| «Немає доступу до задач: permission-denied» | Не опубликованы правила, шаг 12 (вкладка Rules → Publish). |
| «Помилка входу (auth/unauthorized-domain)» | Добавьте домен в шаге 11. |
| «Директор ще не завершив перше налаштування» | Сначала войдите как директор и пройдите часть 3. |
| Изменения сайта не видны после правки файлов | GitHub Pages обновляется 1–2 минуты; обновите страницу. |
